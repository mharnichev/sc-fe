## Условия и границы проверки

Реальные FastAPI-маршруты, PostgreSQL и bearer-авторизация; синтетические клиенты и провайдеры SMS/Telegram, записывающие сообщения только в память. Использован отдельный контейнер `soulcuts-segments-fulltest-20260906`, loopback-порт 55439, уникальные временные схемы; рабочая БД и сервисы не используются. Backend pytest запускается с чистым окружением и запретом внешних сетевых соединений. Никаких реальных рассылок или deploy.

API-ответы успешных segment/connected сценариев не подменяются. Проверка гонки ответов задерживает настоящий ответ backend; проверка ошибки явно инжектирует HTTP 503. Старый `filter-panels.smoke.spec.ts` использует тестовые ответы и учитывается отдельно.

Браузерная проверка — Chromium, desktop и представительный mobile viewport. Safari/Firefox, staging/production, фактическая доставка внешними SMS/Telegram-провайдерами и производительность на реальном объёме клиентов не проверялись. Backend-тесты включают миграцию туда/обратно и очередь 1000 персонализированных получателей; это не нагрузочный benchmark.

## Найденные и исправленные дефекты

1. **Отзыв маркетингового согласия не сохранялся.** API-клиент отправлял `undefined` при `marketing_consent=false` и `opt_out=false`. Теперь передаётся `opted_out`; добавлен unit-контракт и реальный E2E с уменьшением контактной аудитории.
2. **Недоступные подписи календаря и потеря фокуса при Escape.** `BaseCalendar` передаёт ID и aria-связи внутреннему полю, обозначает popup как dialog и возвращает фокус без повторного открытия. Реальный keyboard E2E проверяет абсолютный период.
3. **404 каталога услуг в мастере кампании.** Удалён безусловный запрос несуществующего `/backoffice/booking-services`. При выборе inline-правила услуги лениво загружаются услуги мастеров с правильными BarberServiceID, всеми страницами мастеров и явной ошибкой/повтором загрузки.
4. **Инверсия приоритета в backend SMS-очереди.** В полном suite маркетинг обогнал срочное сервисное сообщение между независимыми workers. При допуске к transport под account lock учитываются ожидающие более приоритетные задачи и уже захваченные, но ещё не отправленные claims. Добавлен детерминированный regression. Полный suite731 и исходный конкурентный тест10 раз проходят после исправления.

5. **Radio игнорировал выбранную модель.** Неуказанный Boolean `checked` приводился Vue к `false` и перекрывал `modelValue`. Явный default `undefined` восстанавливает отображение выбранного режима аудитории, сохраняя legacy checked-поведение. SSR-regression воспроизводил ошибку до правки.
6. **Select терял отображение ранее выбранной услуги после переключения режима.** Неуказанный `modelValue` приводился к `false`, перекрывая legacy `value`. Для обоих необязательных значений установлен default `undefined`; explicit false остаётся допустимым значением. SSR и реальный E2E проверяют восстановление выбранной услуги.

Также исправлены ошибки самих новых тестов: ожидание правильных action endpoints, выбор видимого radio-label/custom listbox и корректная обработка завершения HTTP-запросов. Диагностика игнорирует только наблюдаемое сочетание DELETE + HTTP204 + Chromium `net::ERR_ABORTED` для bodyless ответа; успешное удаление и обновление списка проверяются отдельно. Остальные неожиданные API/console/page ошибки остаются падением теста.
